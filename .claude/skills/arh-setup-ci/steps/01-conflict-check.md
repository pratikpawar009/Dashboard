# Phase 1 — Conflict check

Goal: detect existing CI configs and decide whether to overwrite, merge, or abort.

## Detection

| CI provider       | File path(s) checked                              |
|-------------------|---------------------------------------------------|
| github-actions    | `.github/workflows/*.yml`                         |
| gitlab-ci         | `.gitlab-ci.yml`                                  |
| circleci          | `.circleci/config.yml`                            |
| jenkins           | `Jenkinsfile`                                     |
| azure-pipelines   | `azure-pipelines.yml`, `.azure/pipelines/*.yml`   |

## Behaviour matrix

| Existing file | Action                                                                          |
|---------------|---------------------------------------------------------------------------------|
| Absent        | Proceed to Phase 2; this is the typical greenfield case.                        |
| Present, Harness-stamped (`# harness-managed`) | Diff the new pipeline against existing. Show diff; ask the user before overwriting. |
| Present, NOT Harness-stamped | Stop. Print: `Existing <file> not generated by Harness; refusing to overwrite. Use --force to overwrite or rename the existing file first.` |
| Present, partial overlap (e.g. existing pr-validation.yml + we'd write ci.yml) | Proceed with non-conflicting filename; warn the user the workflows may overlap. |

## Force flag

`--force` (added at the SKILL.md frontmatter as `argument-hint: "[--force]"`) overrides the abort. Even with force, always show a diff before writing.
