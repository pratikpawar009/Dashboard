## Regression check on the `conftest.py` pin — **no regression found**

This is the one thing genuinely worth re-checking this round, per the task brief. Verified on three
independent axes:

1. **T-08's per-test overrides still win.** `services/api/tests/conftest.py::build_app`'s `_build`
   merges `{**_HERMETIC_SETTINGS_DEFAULTS, **overrides}` — the per-call `overrides` dict always wins
   key-for-key over the pin dict, dict-merge semantics unchanged by this edit. Every `build_app(...)`
   call in `test_auth_logout.py` explicitly supplies `frontend_login_url` itself, either via
   `_configured_overrides()` (sets it to a fixture URL) or as an explicit `frontend_login_url=None`
   override on the four "unset → 501" / "unset → no `dashboard_logout` event" tests
   (`test_app_boots_without_raising_when_all_config_unset`,
   `test_logout_returns_501_when_any_required_config_value_missing`,
   `test_logout_501_path_emits_no_dashboard_logout_event`, and the 501 gate parametrization over all
   four required values including `frontend_login_url`). None of these tests ever relied on the pin's
   value in the first place, so the new pin cannot have changed their behaviour — confirmed by the
   full-suite 590/590 pass above, which includes every one of them.
2. **The pin is real, not a masking literal.** Cross-checked
   [[conftest-pins-shadow-shipped-defaults]] concern directly: `Settings.model_fields["frontend_login_url"].default`
   and `Settings.model_fields["persona_precedence_order"].default` are both independently confirmed
   `None` — identical to the pinned value, and matching `README.md`'s documented `Default: None
   (unset)` row for both env vars (added by T-10, unchanged this round). No divergence exists between
   the pin and the shipped default to hide.
3. **Empirical shell-leak probe** (read-only, no source edits): set `FRONTEND_LOGIN_URL` in the shell
   to a bogus value, then compared `Settings()` (unpinned — picks up the leak: returns the bogus URL)
   against `Settings(**_HERMETIC_SETTINGS_DEFAULTS)` (pinned — returns `None` regardless). Then ran
   `test_me.py` — a file whose 12 tests never mention `frontend_login_url` anywhere — with the leaked
   env var still exported: **12 passed**, unaffected. This is the exact hermeticity gap AF-01 closes:
   before the fix, roughly 20 other test files that call `build_app()` without ever touching
   `frontend_login_url` (`test_me.py`, `test_auth_accessibility_scope.py`, `test_auth_callback.py`,
   `test_personal_usage.py`, `test_auth_refresh.py`, `test_overview.py`, `test_programs.py`, the three
   `tests/perf/*.py` files, etc.) would have silently inherited a developer's shell/`.env` value for
   this field instead of a deterministic `None`. Confirmed closed.
