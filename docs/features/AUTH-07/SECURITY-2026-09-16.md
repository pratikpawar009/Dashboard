### F-1 — New unauthenticated authlib decode call site in `_log_dashboard_logout` (OWASP A07 / A09)

- Source: `checklist/auth`
- Severity: Medium
- Category: auth
- Files:
  - services/api/app/auth/oidc.py (`oidc_logout` + `_log_dashboard_logout`) - see `services/api/app/auth/oidc.py`
  - Backing dep: `authlib==0.15.6` (declared in `services/api/pyproject.toml`, unchanged by this diff)
- Issue: `GET /auth/logout` accepts an **optional** bearer (`_http_bearer = HTTPBearer(auto_error=False)`), by design (D-08 — logout must not be blocked by a decode failure). The optional bearer is forwarded into `_log_dashboard_logout`, which calls `authlib.jose.jwt.decode(credentials.credentials, signing_key)` inside a `try/except Exception: pass` block. Under the pinned `authlib>=0.15,<1.0` / `0.15.6` installed, several published advisories affect exactly this JWS deserialization path — CVE-2025-61920 (unbounded JWS/JWT header/signature segments, CPU/RAM DoS), CVE-2025-59420 (JWS `crit` "must-understand" bypass), CVE-2026-27962 (JWK header injection when a resolver returns `None`). The **DoS surface (CVE-2025-61920)** is symmetrically exposed by AUTH-01's shipped `/auth/callback` / `/auth/refresh` → `_log_dashboard_login` path against the just-returned Keycloak token, but AUTH-07 adds a **new** call site that decodes an **attacker-supplied** bearer on an endpoint that **does not require prior authentication**. Practical impact is bounded by Starlette/h11's default 16 KiB request-line/header cap (which prevents the multi-hundred-MB PoC token from reaching Python), and the JWK-injection CVE is not reachable here because `signing_key` is resolved through `jwks_cache.get_signing_key(kid)` (never `None` — it raises 401 on a miss). But the new decode call site does widen the attack surface against a **known-vulnerable dep** by a non-trivially different vector (bearer forwarded by the frontend rather than freshly-minted-by-Keycloak).
- Fix (either is sufficient):
  1. Impose an explicit token byte cap in `oidc_logout` before `_log_dashboard_logout` runs (e.g. reject/skip decode when `len(credentials.credentials) > 8_192`), defense-in-depth against the raw-size DoS class, aligned with `.claude/rules/security-baseline.md` § "Parsing safety" (bounded-reader pattern); or
  2. Track an authlib upgrade to `>= 1.6.12` in a dedicated deps-upgrade story — recommended as a follow-up regardless (fixes all in-tree authlib CVEs on this code path in one bump).
- Verdict impact: Non-blocking — pre-existing dep pinning inherited from `main`; AUTH-07 does not modify the manifest. Classified Medium because the new call site is unauthenticated, but downgraded from High by (a) the h11 header-size cap in front of it and (b) the pre-existing symmetric exposure on `/auth/callback` / `/auth/refresh`.
