- No `eval`, `os.system`, `subprocess`, or file uploads introduced. PASS.
- Client-supplied query parameters cannot influence scoping: `TC-18` in `test_programs.py` asserts a `?programs=` query string is ignored; verified in REVIEW.md as the NFR-security test. PASS.

### Authentication and authorization

- Every path enforces authn: `Depends(get_current_user)` on the route; the handler cannot execute without an authenticated `CurrentUser`. PASS.
- Every path enforces authz:
  - `program_visibility(current_user, _VETO_GATE_SENTINEL_PROGRAM_ID)` is called exactly once as a session-validity veto gate before scoping (FR-2/C-2). The sentinel `program_id` is named and documented at the call site; `program_visibility` is defined (in `app.core.rbac`) as an open-aggregate check that provably never reads its own `program_id` argument, so the sentinel cannot leak or bypass anything. Verified by REVIEW.md's TC-11 spy (`len(visibility_calls) == 1` against 5 seeded programs). PASS.
  - Persona resolution is fail-closed: `PersonaNotFoundError` is caught before its own base class `PersonaResolutionError`; both branches log at WARNING and raise `HTTPException(403, "Access denied")` from `None` — no traceback chained, no `500` path. PASS.
  - Scoping: `cio` → full table; every other persona → `WHERE program_id IN current_user.programs` (list drawn from `CurrentUser`, never a client input). Empty `session.programs` → `in_([])` yields zero rows and a `200 {"programs": []}`, never an error path (AC-2/AC-4). PASS.
- Tokens scoped / rotated / sessions invalidated: out of scope for this endpoint (owned by AUTH-01); this diff introduces no session, token, or credential handling. N/A.

## Stack-pattern pass

### fastapi-patterns

- One `APIRouter` per resource under `app/api/programs.py`, exporting `router`, wired in `app/main.py` in the include-router block — matches the "one router per resource" idiom. PASS.
- Handler is a thin async `list_programs` — persistence-adjacent logic (WHERE-clause branching, filtering) is minimal and confined to the route. PASS.
- Error envelope: relies on `register_exception_handlers`; no ad-hoc error dict returned. PASS.
- Pagination bounds on a list endpoint: the anti-pattern list requires `page`/`page_size` `Query` bounds. This endpoint deliberately omits them — REQUIREMENTS.md § Scope records "No pagination — org sized at ~9 programs (NFR-004 seed fixture)"; research risk #7 accepted this at the Product Gate. REVIEW.md explicitly signs off. Not a security finding today (no user-controlled unbounded fan-out, authenticated caller, scoped by `session.programs`), but recorded here for traceability if the org outgrows the ~9-row seed.

### pydantic-patterns

- Separate response models (`ProgramEntry`, `ProgramsListResponse`) under `app/schemas/programs.py`; no config/env fields leaked in. PASS.
- `Field(..., description=...)` on every field; `dot_style: str = Field(..., alias="dotStyle")` with `populate_by_name=True` — wire-compatible with ADR-0005's exact `{program_id, label, href, dotStyle}` key set. REVIEW.md CF-02 already records the plan-vs-implementation naming variance as informational, contract-tested via TC-06 key-set equality. Not re-flagged here. PASS.

### postgres-patterns

- All DB access flows through `app.core.db.get_db` (`Depends(get_db)`), never a direct `os.environ["DATABASE_URL"]` read. PASS.
- Query is SQLAlchemy 2.0 declarative `select(ProgramSummary)...in_(...)` — parameterised, no raw SQL, no `execute("...")` string. PASS.
- Pagination note as above — the postgres-patterns anti-pattern list also calls this out; accepted at the PRD gate.
