**Live end-to-end corroboration beyond the mocked vitest suite** (real dev-bypass tokens, real running servers, real Keycloak realm for the refresh calls):

- `POST /auth/dev-bypass` → 200, real token pair minted.
- `GET /login` (web) → 307 to a real Keycloak authorization URL, never a FastAPI origin (AC-2). **Observation, not a defect**: with this validation environment's real `.env` (`OIDC_REDIRECT_URI` unset — confirmed via `settings.oidc_redirect_uri is None`), the relayed `redirect_uri` param resolves to the API's own `http://localhost:8000/auth/callback`, matching `.env.example`'s own documented unset-fallback behaviour exactly (`_resolve_redirect_uri`). Restarting the API with `OIDC_REDIRECT_URI=http://localhost:3000/callback` exported (matching T-01's new `.env.example` default, no file edited) reproduced the intended frontend-first redirect_uri immediately — confirms AC-1/AC-2/AC-3's wiring is correct; only *this environment's* real `.env` hasn't been synced to the new template default, which is expected (`.env` is git-ignored/per-deployment, and T-01's Constraints scope this story to the `.env.example` default only).
- `GET /callback` (web, no code/state) → 307 to `/login`, matching the exchange-failure branch (D-04).
- Built a `dashboard_session` cookie by hand (`StoredSession` JSON shape, per `MANUAL-TESTING.md` step 2) from a fresh dev-bypass token:
  - `GET /programs/prog-042` (web, server-rendered, cookie attached) → page 200, renders `ProgramDetailErrorPanel`; API log shows `GET /api/overview/program-detail/prog-042 → 404` (not 401) — proves `page.tsx`'s server-side bearer attach worked (AC-5), a 404 on an unseeded id being the documented "still proves acceptance" case.
  - `GET /api/proxy/program-detail/prog-999` (web, **no** Authorization header sent by the client) → 404 from the same server-to-server call pattern — proves the proxy attaches its own bearer, the browser never needs one (AC-10, D-08/D-10, ADR-0008).
  - `GET /api/proxy/programs` (web, cookie only) → 200 `{"programs":[]}` — FastAPI 403'd (persona config unseeded in the throwaway smoke DB), and the client module degraded to `[]` exactly as T-10/T-14 specify (graceful degradation, not a defect).
  - Near-expiry cookie (`expiresAt` 10s out) + real dev-bypass `refreshToken` → `GET /api/proxy/program-detail/...` → **401 `{"error":"session_expired"}`**, `Set-Cookie: dashboard_session=; Expires=1970...` (cookie cleared). API log confirms the proactive refresh (`POST /auth/refresh`) fired *before* any `GET /api/overview/...` line — the guarded call never ran, matching AC-6's ordering — and the refresh itself got a real `401` from Keycloak (`https://lab.apexonlab.com/.../token` → `400`, mapped to `401`). No raw Keycloak body ever reached the client response (AC-8/FR-5). This is **AF-03**, already triaged in `FLAGS.md` — a dev-bypass refresh token can never succeed against real Keycloak — confirmed live, not a new finding.
