# ING-03 — Decisions

Decision log for `POST /api/ingest/{kind}` — `kind="artifacts"` (Q-01 resolves the URL topology; Q-02 the response shape). Header slugs (`blast:`/`rev:`/`adr:`) are machine-greppable per the `decide` skill. PLAN.md §1 is a one-line pointer to this file — decisions are not duplicated there.

### D-01: Adopt generic `POST /api/ingest/{kind}` router; retire `POST /api/ingest/files` URL · blast:system · rev:medium · adr:ADR-0013

**Context**: Q-01 (Product Gate 2026-09-13) chose a single generic path `POST /api/ingest/{kind}` over two independent handlers. ING-02 (`phase: review`, PR #296) had shipped `POST /api/ingest/files` for `kind="activity"`; this decision retires that URL in favour of `/api/ingest/activity` (kind-param resolved), and the new artifacts route `/api/ingest/artifacts` is the generic route with `kind="artifacts"`. The trade-off is coordinated pre-merge refactor of an in-review shipped route (byte-for-byte semantics preservation for `kind="activity"` — same body, same response fields, same 400/401/403/413 ordering, same ADR-0012 background dispatch) versus letting the two-vocabulary drift ING-02 D-03 was already fighting re-appear at the router tier. Downstream consumers of `ingest-files-api` (`ING-04`, `ING-06`, `ING-09` per `docs/requirements/api.md#ingest-files-api`) are all still to-be-planned and bind against whatever URL topology ships in this cycle — no external caller has committed to the old `/files` URL.

**Decision**: `POST /api/ingest/{kind}` becomes the single handler on the shared `/api/ingest` router. `kind` is a path-param, validated against `services/api/app/core/ingest_kind.py::_ACCEPTED_KINDS` (extended to `frozenset({"activity", "artifacts"})` in the same PR) at the router tier BEFORE bearer auth. Dispatch by kind after the accept + auth + body checks: `"activity"` → `app.services.activity_ingest.ingest_files(...)` (unchanged, ING-02); `"artifacts"` → `app.services.ingest_artifacts.ingest_artifacts(...)` (new). No compatibility alias for `/api/ingest/files` — `kind="files"` is NOT accepted. Promoted to ADR-0013 because it changes the shared `ingest-files-api` route URL contract (`blast:system`, `rev:medium`); the ADR captures the semantics-preservation contract for `kind="activity"` and pins the ING-02 test-file URL-constant edits (T-05) as the audit surface for byte-for-byte preservation.

### D-02: `IngestArtifactsResponse` mirrors `IngestFilesResponse` field-for-field · blast:feature · rev:mechanical · adr:—

**Context**: Q-02 (Product Gate 2026-09-13) chose `{rows_received: int, rows_upserted: int, rejections: list}` for the artifacts response, mirroring ING-02's `IngestFilesResponse` symmetrically. Alternatives considered: (a) minimal `{"status": "ok"}` per the Research Solution-sketch, (b) return the upserted rows verbatim. (a) forces future consumers to poll `program_artifacts` for confirmation; (b) leaks the whole write payload back over the wire for no downstream reader today (`consumed_by: [ING-04]` — the MCP push tool needs a count, not the rows). Symmetric shape lets one client parser handle both `/activity` and `/artifacts` responses.

**Decision**: create `services/api/app/schemas/ingest_artifacts.py::IngestArtifactsResponse` with exactly `rows_received: int`, `rows_upserted: int`, `rejections: list[RejectionEntry]` (RejectionEntry `{index: int, reason: str}`, imported from `app/schemas/ingest_files.py` so both routes share the same rejection-entry type — reuse over re-definition). On the artifacts happy path `rejections` is always `[]` because the canonical-type check runs router-tier (400, zero writes); the field is present for symmetry only. The 200-success path returns `rows_received == rows_upserted == len(counts)`; no partial-commit case exists (see D-03 / DATA-DESIGN.md § 5). `docs/requirements/api.md#ingest-artifacts-api` (T-14) gains the `response_body` field pinning this exact shape.

### D-03: ADR-0012 does NOT apply to artifacts — `ingest_artifacts` service MUST NOT import or dispatch any rollup rebuild · blast:feature · rev:mechanical · adr:—

**Context**: ADR-0012 (`rebuild_org_rollups()` runs out-of-band via `BackgroundTasks`) applies to `kind="activity"` because BED-05's org-scope rollup reads `usage_events`. `program_artifacts` is a leaf counts table with no rollup source relationship — nothing under `services/api/app/services/rollup_rebuild.py` reads it. PRD § Constraints pins this explicitly and § Scope § Out enumerates "any dispatch of `rebuild_program_rollups()` or `rebuild_org_rollups()`". The risk that a well-meaning future contributor copies `activity_ingest.py`'s signature (which takes `on_org_rebuild: Callable[[], None]`) into `ingest_artifacts.py` is real; a runtime assertion is unreliable because the copied code compiles and runs.

**Decision**: `ingest_artifacts.ingest_artifacts()`'s signature is `(db, program_id, counts, as_of, token_label) -> IngestArtifactsResponse` — no `on_org_rebuild` parameter, by construction. The module docstring pins ADR-0012 non-applicability explicitly and contrasts with `activity_ingest.py`. Enforced by a MODULE-LEVEL unit test `services/api/tests/unit/test_ingest_artifacts_no_rollup_dispatch.py` (T-10, F-16) that asserts `services.ingest_artifacts` does not import `rebuild_program_rollups` or `rebuild_org_rollups` from `app.services.rollup_rebuild` — a static-code guard that catches copy-paste before runtime. The generic router (F-04) also passes no callable to the artifacts dispatch branch — `background_tasks` is unused for `kind="artifacts"`.

### D-04: Rename `services/api/app/api/ingest_files.py` → `ingest.py` (`git mv`, preserves history) · blast:feature · rev:mechanical · adr:—

**Context**: Q-01 makes the router generic — it no longer hosts a `/files` route. Options: (a) rename the module file to match the new semantics (`ingest.py`), (b) keep the legacy filename `ingest_files.py` and change only the route + docstring. (b) minimises PR diff (one module docstring + route path change) but leaves a misleading grep-history: a future reader searching for the generic ingest router by module name would not find it; and `services/api/app/main.py` imports `from app.api.ingest_files import router as ingest_files_router` which reads as legacy. (a) is a mechanical rename via `git mv` (history-preserving) plus one import-line update in `main.py`. No test files import from `app.api.ingest_files` today (verified — router is exercised via `create_app()`); nothing else needs updating.

**Decision**: (a) — `git mv services/api/app/api/ingest_files.py services/api/app/api/ingest.py`. `services/api/app/main.py` (F-06) updates its import to `from app.api.ingest import router as ingest_router` and the include call. The module docstring (in the renamed file) records the ING-02→ING-03 semantic evolution and points at ADR-0013. Test files under `services/api/tests/unit/test_ingest_files_*.py` keep their filenames per surgical-changes discipline — those tests still cover the activity-kind path specifically, and renaming them is out of scope for ING-03 (they only need URL-constant edits per D-01 / T-05). Reversible via `git mv` back.

### D-05: NFR-performance perf test reuses ING-02's `@pytest.mark.perf` marker and `-m 'not perf'` default addopts — no new runner setup · blast:feature · rev:mechanical · adr:—

**Context**: PRD NFR-performance is p95 < 300 ms for a single ≤5-row upsert with no rollup rebuild. TC coverage GAP records this as user-imposed (2-TC cap; NFR-performance intentionally not in `docs/test-cases/ING-03.json`) and PRD § Approvals defers it to "implementation-time evidence and unit tests, not gated by the test-case manifest". A perf test is nevertheless required to exercise the budget under a realistic seeded state and to prevent silent regression. ING-02 D-04 already established the `perf` pytest marker + default addopts `-m 'not perf'` in `services/api/pyproject.toml:58-61` — a shared toolchain seam.

**Decision**: `services/api/tests/perf/test_ingest_artifacts_perf.py` (F-19, T-13) declares `@pytest.mark.perf` and lives in the existing `services/api/tests/perf/` directory (created by BED-05 F-08, populated by ING-02 F-20). No new pytest marker, no new addopts entry, no new runner install — reuses the established seam. Default `pytest` invocation skips the perf test (via `-m 'not perf'`); CI or a developer opts in with `pytest -m perf`. Unlike ING-02's perf test, this one does NOT need a large seed dataset (`program_artifacts` is at most 5 rows/program and there is no accumulated-table cost curve — the unique-index `ON CONFLICT` lookup is O(log n)); the fixture seeds two other programs' artifacts to prove program-scope isolation and measures the ≤5-row upsert on a third program. Budget check against the 300 ms p95 target is asserted in-test (fail-loud, not observation-only).
