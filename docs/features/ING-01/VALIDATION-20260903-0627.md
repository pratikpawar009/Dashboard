### F-2-equivalent — `--program-ids ""` mints a fully unscoped, never-expiring, allow-all token  (CRITICAL — independently reproduced)

- Requirement: `ING-01-FR-2` (mint failure contract) / `DECISIONS.md` D-05 ("a supplied value collapsing to zero usable elements ... raises a usage error, non-zero exit, ... no DB row, nothing on stdout")
- Not tied to a declared TC — this is a coverage gap in the manifest itself, discovered by independently checking what the 4 D-05 regression tests actually assert versus what D-05's text promises (see this repo's validation-agent memory: coverage claims get verified by direct testing, not accepted because the suite is green).
- Repro (fresh subprocess, fresh disposable `bed03-manual:5443/dashboard_test`, migrated to head, `DATABASE_URL` explicit — never the dev DB):
  ```
  $ uv run python scripts/mint_ingest_token.py --label f2-independent-empty-string-check \
      --user-email f2@example.com --program-ids ""
  exit code: 0
  stdout: hrn_pat_<REDACTED-64-HEX>   # real minted token, redacted by the orchestrator before commit
  stderr: (empty)
  DB row: allowed_program_ids = [], count = 1
  ```
- Expected (per D-05 / FR-2): non-zero exit, stderr message, no DB row, no stdout token — same outcome as `--program-ids " "` or `--program-ids ","`.
- Actual: exit 0, a valid unscoped/never-expiring token printed and persisted.
- Root cause: `scripts/mint_ingest_token.py:87`, `_parse_program_ids`'s `if not raw:` guard is `True` for both `raw is None` (genuine omission) and `raw == ""` (a value the caller explicitly supplied — argparse assigns `""` to `args.program_ids`, distinct from `None`, confirmed empirically). Both routes return `[]` before the trim/usage-error logic ever runs.
- Realistic trigger: `--program-ids "$IDS"` where `$IDS` is an empty or unset shell variable — at least as plausible an operator mistake as a bare space or comma, and the one D-05's own fix does not cover.
- `services/api/README.md`'s new claim *"a typo cannot silently mint an unscoped token"* (added this round, § Ingest token auth) is therefore inaccurate as currently shipped for this one input shape.
- Cross-check: matches `docs/features/ING-01/REVIEW.md` F-2 (CRITICAL, verdict BLOCKED) exactly — arrived at independently (own repro script, own fresh DB) before reading that report's line-by-line detail.
- Suggested fix (same as code-review's): distinguish `raw is None` (omission) from any other value before the trim pass, so `""` reaches the same trim → empty → `ValueError` path as `" "`/`","`. Add a 5th `*_regression_f1` test for `--program-ids ""`.
- Action: feeds the next fix loop. Not a carry-forward/deferral candidate — this is the accepted-risk boundary (ADR-0006 §3's *deliberate* allow-all-by-omission) being reachable by *accident*, which ADR-0006 § Consequences explicitly frames as the risk to guard, not accept expanded.
