# ING-01 — Decisions

Story-level decision log. ADR-0006 already settles token format, mint surface, scope semantics,
and lifetime — entries here cover implementation-surface choices ADR-0006 leaves open.

### D-01: `get_ingest_token()` takes `program_id` directly; the FR-3 scope check runs inside the dependency, not the route handler · blast:service · rev:mechanical · adr:—

**Context**: ADR-0006 §3 fixes the scope-check *logic* but not *where it runs*. Research's own Conditions for GO (Condition 4 / Risk register #4) recommended deferring the FR-3 check to the route handler so `get_ingest_token()` stays parameterless, mirroring `get_current_user()`. But `ING-01-FR-4`'s table folds the FR-3 scope outcome into the same "auth-check dependency" contract, and `ING-01-TC-17` inspects "the `get_ingest_token` / scope-check function signature to confirm `program_id` is a required parameter distinct from the resolved token record's fields" — this has to be settled before ING-02/03/07 build against the `ingest-token-auth` contract.

**Decision**: `get_ingest_token(program_id: str, credentials: HTTPAuthorizationCredentials | None = Depends(HTTPBearer(auto_error=False)), session: AsyncSession = Depends(get_db)) -> IngestToken` lives in `app/core/ingest_auth.py` — a new module parallel to, and never importing from, `app/core/auth.py` (FR-6 structural isolation). `program_id` is an ordinary function parameter FastAPI resolves the same way it resolves any path/query parameter of that name on the route that declares `Depends(get_ingest_token)` (ING-02's concern to wire) — never read off the resolved `IngestToken` row. Both the FR-4 401 classification and the FR-3 403 scope check run inside this one dependency call, which returns the resolved `IngestToken` SQLAlchemy row directly as the principal — no separate `IngestTokenRecord` DTO; the model already carries every field a caller needs and a parallel dataclass would just drift from it.

### D-02: Mint script opens its own `SessionLocal` session and prints the raw token only after a successful commit · blast:feature · rev:mechanical · adr:—

**Context**: `scripts/mint_ingest_token.py` runs outside any HTTP request, so it cannot use the `get_db()` FastAPI dependency (`app/core/db.py`) every other DB-touching code path in this service uses. `ING-01-FR-2` requires that a failure leave no DB write and print no token — including a DB-connectivity failure, not just an argparse usage error — so the ordering between "write" and "print" has to be atomic from the operator's point of view.

**Decision**: the script imports `SessionLocal` from `app.core.db` directly and opens one session per invocation via `async with SessionLocal() as session:`, mirroring `get_db()`'s own body without the FastAPI-request wrapper. Token generation and hashing happen in memory first; the `IngestToken` row is added and `await session.commit()` runs inside a `try` block; the raw token is written to `stdout` only after that commit succeeds. Any exception during session construction or commit (including an unreachable `DATABASE_URL`) is caught by one `except Exception`, its message printed to `stderr`, and the process exits via `sys.exit(1)` — never partially committing, never printing a token whose row did not persist.

### D-03: `ING-01-TC-21` wires a throwaway app + a real dual-dependency route, not two isolated function calls · blast:feature · rev:mechanical · adr:—

**Context**: `ING-01-FR-6` requires evidence that `get_ingest_token()` and `get_current_user()` "resolve independently" on the same route. That claim only means something once both dependencies actually run through FastAPI's own resolution machinery on one path operation — calling each function directly with hand-built arguments would prove the two functions don't share code, not that FastAPI resolves them independently when both are declared as `Depends()` on the same route.

**Decision**: `tests/unit/test_ingest_token_isolation.py` builds one throwaway `FastAPI` app (mirroring `tests/unit/test_auth_jwt_validation.py`'s local `_build_app` helper — never `app.main.create_app`) with a single mock route exposing both `Depends(get_current_user)` and `Depends(get_ingest_token)` as two separate response fields, then drives it over `httpx.AsyncClient`/`ASGITransport` (via `conftest.py`'s `async_client_for`) twice: once with a dev-bypass-signed JWT (asserting the ingest-token field 401s), once with a minted ingest token seeded into the test DB (asserting the JWT field 401s).

### D-04: `--program-ids` is optional at the mint CLI, defaulting to an empty (allow-all) scope · blast:feature · rev:mechanical · adr:—

**Context**: ADR-0006 §3 fixes that an empty `allowed_program_ids` means allow-all at the auth-check layer, but leaves open whether the mint CLI should let an operator reach that state by omission, or force an explicit `--program-ids "*"`/id-list every time. `ING-01-TC-03`'s missing-required-argument matrix tests only `--label` and `--user-email`, and the PRD's accepted-risk NFR frames the most-permissive credential as "the one produced by omitting a mint flag" — both already commit to `--program-ids` being optional, not required.

**Decision**: `--label` and `--user-email` are the only `required=True` argparse flags. `--program-ids` is optional; omitted or empty, it produces `allowed_program_ids=[]` (ADR-0006 §3's accepted allow-all default). When given, its value is split on `,` into the stored list — the literal `"*"` splits to the single-element `["*"]` with no special-casing needed.

### D-05: `--program-ids` trims and drops whitespace around each element; a supplied value collapsing to zero elements is a usage error, not allow-all · blast:feature · rev:mechanical · adr:—

**Context**: F-1 (code-review MEDIUM, raised at the Validate ∥ Review gate) found `_parse_program_ids` stored raw, untrimmed comma fragments, so `--program-ids "a, b"` silently under-permitted the token — `_check_program_scope` does exact-string membership, and `" b"` never matches a caller's `program_id="b"`. Fixing it naively by returning `[]` whenever trimming empties the list would have created a **new fail-open path** the original bug did not have: `--program-ids " "` or `--program-ids ","` — plausible typos — would collapse to `[]`, which ADR-0006 §3 and D-04 define as allow-all, unscoped and never-expiring. A typo would mint the most permissive credential the system can issue.

**Decision**: `_parse_program_ids` trims each comma-separated element and drops empty ones (`"a, ,b"` → `["a", "b"]`; `"*"` → `["*"]`, unaffected). D-04's allow-all `[]` result stays reachable **only** by omitting `--program-ids` entirely (`raw is None` — see the D-05a amendment below, which removes `""` from this set). A *supplied* value with zero usable elements after trimming raises a usage error — non-zero exit, message on stderr, no DB row, nothing on stdout — consistent with `ING-01-FR-2`'s existing failure contract. This is not an ADR-0006 change: scope semantics (§3) and D-04's omission-means-allow-all are both untouched; it narrows only what counts as a non-empty supplied value at the mint CLI's input-validation boundary. Regression tests: the four `*_regression_f1` cases in `tests/unit/test_mint_ingest_token.py`.

### D-05a (amends D-05): only `raw is None` counts as omission — a supplied `--program-ids ""` is a usage error · blast:feature · rev:mechanical · adr:—

**Context**: D-05 as first written put `raw is None` **or** `""` in the omission set, and the implementation faithfully encoded that as `if not raw: return []`. Round 2 of the Validate ∥ Review gate caught the consequence: `validation-agent` (CRITICAL) and `code-review-agent` (F-2, CRITICAL) independently reproduced `--program-ids ""` minting a fully unscoped, never-expiring, allow-all token — exit 0, token on stdout, a committed row with `allowed_program_ids=[]`. The realistic trigger is `--program-ids "$IDS"` with an unset or empty shell variable, i.e. exactly the scripted-invocation case an operator is most likely to hit. D-05 closed `" "`, `","`, `",,"`, `" , "`, tabs and newlines but left this one shape open, because the guard could not distinguish an absent flag from a supplied empty value.

**Decision**: the omission set is **`raw is None` only**. A supplied `--program-ids ""` is a usage error on the same terms as `" "` or `","` — non-zero exit, message on stderr, no DB row, nothing on stdout. Concretely `if not raw:` becomes `if raw is None:`. D-04's omission-means-allow-all and ADR-0006 §3's scope semantics are both unchanged; this narrows only what the mint CLI treats as omission. Amended rather than rewritten in place so the gate's catch stays legible: the original D-05 shipped a fail-open path and the gate is what stopped it.
