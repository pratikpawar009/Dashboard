## Observations (not TC failures)

Recorded here rather than as failures because no declared TC asserts them and nothing is red. See CF entries in the hand-off for the ones needing an owner.

1. **`DATA-DESIGN.md § 5`'s single-read claim is now conditional.** It states the `asyncio.Lock` double-check means "a burst of concurrent cold calls issues at most one database read, not one per caller." True on the success path (proven by `test_concurrent_cold_calls_collapse_to_one_underlying_select`: 10 concurrent callers → 1 factory call). **Not true on the timeout path** introduced by D-04: `[C]` measured 3 concurrent callers issuing 3 separate SELECTs, because each timed-out caller releases the lock and the next one re-checks an empty cache and queries afresh. § 5 predates D-04 and was not revised alongside it. → CF-BED-04-03.
2. **Queue-depth latency under a sustained stall is linear, not flat.** `[C]`: 3.015 s / 6.035 s / 9.055 s for callers 1–3. Every caller is bounded (F-1's actual defect — an unbounded hang — is closed), but the Nth queued caller on a shared instance waits N × 3.0 s. Harmless for BED-04 (no route, no shared instance) and material for OVW-01/ARC-01/DEV-01/PMD-01/EMD-01 if they share one instance per app. → CF-BED-04-03.
3. **The timeout log `reason` hardcodes the bound.** `freshness.py:159` emits `"system_metadata query exceeded 3.0s timeout"` as a literal rather than interpolating `_QUERY_TIMEOUT_SECONDS`. Observed empirically: the regression test patches the constant to 0.01 s and the log still claims 3.0 s. Precedent-consistent (`persona_resolver.py:197` does the same) and already raised as a LOW by the concurrent code review — noted here only as independent corroboration, not double-filed.
4. **Pre-existing `ruff format` violation at `README.md:26`** (`## Session factory` section). Confirmed pre-existing, not BED-04's: `git diff -U0 -- services/api/README.md` shows a single hunk `@@ -271,0 +272,23 @@` — the story added lines 272-294 only and never touched line 26. BED-04's own four Python files and its README Python fence are `ruff format --check` clean.
5. **Untracked `apps/web/pnpm-workspace.yaml`.** Not in BED-04's `file_plan`, not referenced by any task; an environment artefact from a prior pnpm invocation. Flagged so it is not silently swept into this story's commit.
6. **`state.json` phase reads `plan-implementation`** and its two round-1 `pending_carry_forward` entries (CF-BED-04-01/02) are intact — consistent with GATE MODE, where the orchestrator is the single writer. This report wrote neither `state.json` nor `features.json`.
