### Unmet stated NFR — the DB read has no bounded wait

**Judgement: unmet-NFR, not a review-style improvement.** Reached independently from the files; it converges with the concurrent `code-review-agent`'s HIGH F-1 but on a narrower and partly different factual basis, and one of that finding's two citations does not hold up.

The requirement text (`docs/features/BED-04/REQUIREMENTS.md:46`, `## Non-functional requirements`):

> Performance: Per `.claude/rules/performance-baseline.md`: cache TTL and its invalidating event are documented — 300s, TTL-expiry only, because the writer is out-of-process (see Constraints). **No retry, no unbounded wait; the single read inherits the session factory's timeout.**

Three assertions; the third is the stated *mechanism* for the second:

| Assertion | Status |
|---|---|
| TTL + invalidating event documented | met — 300s / expiry-only, documented in `freshness.py`, README, `api.md` |
| No retry | met — no retry construct anywhere in `freshness.py` |
| **No unbounded wait** | **unmet** |
| **"inherits the session factory's timeout"** | **false — there is no such timeout to inherit** |

Verified rather than assumed:
- `app/core/db.py:17` is `create_async_engine(settings.database_url)` — no `connect_args`, no `pool_timeout` override, no `execution_options`.
- `grep -rn "timeout" services/api/app/` returns hits only in `persona_resolver.py` (3.0s Tier-3), `oidc.py` / `jwks.py` (5.0s HTTP), and `rbac.py` (a comment). Nothing in the DB path.
- No `statement_timeout` is set in the DSN, in `Settings`, or in `.env.example`'s `DATABASE_URL` shape.
- SQLAlchemy's default `pool_timeout=30` bounds only the wait to check a connection *out of the pool*; it bounds neither the TCP connect (psycopg3's `connect_timeout` defaults to unset) nor statement execution. So the one thing that *is* bounded by default is not the thing the NFR promises.

Why this is a requirement gap rather than a taste preference: the sentence is normative prose in the PRD's NFR section, invoked "Per `.claude/rules/performance-baseline.md`" — whose text is "I/O has explicit timeouts. No silent infinite waits." The story promised a bounded wait and cited a mechanism that does not exist. A stated requirement that the shipped code does not deliver is exactly what a validation phase adjudicates, and the fix pattern was already in the repo: `persona_resolver._resolve_tier3` — the *same* module BED-04's own `DECISIONS.md` D-01 names as "the precise model to follow" — wraps the identical `session.execute(...)` shape in `wait_for(_query(), timeout=_TIER3_TIMEOUT_SECONDS)` (`persona_resolver.py:194-197`). The mitigation needed no shared-code change.

Independent amplification assessment (concurring with review): the query runs inside `async with self._lock` (`freshness.py:106-114`), so a stalled connection blocks every coroutine sharing that `FreshnessAccessor` instance, not only the one that triggered it. D-01 explicitly anticipates instance sharing across concurrent requests once a consumer story wires one up, so the blast radius grows at first real use rather than staying local.

**Correction to the review's finding, on independent check:** review F-1 attributes the "inherits the session factory's timeout" claim to *both* `REQUIREMENTS.md` § NFR Performance *and* `DATA-DESIGN.md` § 8. Only the first is true. `DATA-DESIGN.md` § 8 (`## 8. Query-path & access-path performance`) contains three bullets — one indexed PK SELECT per miss, O(1) warm path, no pagination — and no timeout language; `grep -rn -i "timeout\|inherit" docs/features/BED-04/*.md` returns no hit in `DATA-DESIGN.md` at all. Whoever fixes this needs to correct **one** document, not two.

**Scope note (keeps blame proportionate):** the *engine-level* absence of a timeout in `app/core/db.py` is pre-existing and repo-wide — every `SessionLocal` consumer (`rollup_rebuild`, `programs`, ingest-token auth) shares it, and BED-04 did not introduce it. What BED-04 owns is (a) an NFR sentence asserting a bound its own code does not have, and (b) declining a local `wait_for` that its own cited precedent demonstrates. Both are addressable inside this story's file set.

No declared TC covers a timeout — `BED-04-NFR-performance`'s covering case (TC-03) tests the p95 budget and the TTL boundary only — so this gap produces no red test, only an absent one. It is reported here as a requirement-vs-code divergence, and it is the sole reason this report is PARTIAL rather than PASS.
