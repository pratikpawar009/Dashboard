## CF-1 re-assessment (focus item 3) — **KEEP, REWORDED (narrowed); do not drop**

The fix closes the substantive half of CF-1 and leaves the mechanism half open.

**Closed.** The real damage CF-1 described was that every `build_app()` test booted with the *retired* scope string. That is gone: the pin now carries the shipped value, and the inert `program_group_prefix` kwarg is deleted rather than left dead. This was the wide-blast-radius part, and the blast-radius experiment shows the change is complete and coupled to exactly one assertion.

**Not closed: the shadowing mechanism survives — only the pinned value changed.** `oidc_scope` is still a key in `_HERMETIC_SETTINGS_DEFAULTS`, i.e. still a constructor kwarg at the highest precedence tier. So `test_auth_oidc_login.py:81` still does not read `Settings.oidc_scope`'s field default; it reads the conftest pin, which now merely *happens to equal* it.

I proved this rather than inferred it. Using a read-only plugin to simulate a regression of the shipped default (no source-tree write), then running the very test in question:

```
CONTROL   (shipped default 'openid profile email')          -> 1 passed
EXPERIMENT(shipped default regressed to '…email groups')     -> 1 passed   ← unchanged
```

The test cannot distinguish the two. Under the same regression the Settings-level guard behaves correctly, which confirms the probe was real and the coverage split is exactly as described:

```
tests/unit/test_auth_config.py -> 1 failed, 36 passed
E  AssertionError: assert 'openid profile email groups' == 'openid profile email'
```

**Consequence for the new comment.** The replacement comment at `test_auth_oidc_login.py:81` says this assertion "proves the shipped default actually reaches Keycloak's authorization request" and instructs "keep it reading the default (do not pin a scope override on this test)". Both halves are inaccurate in the same direction as the comment they replaced: the test does not read the default, and a scope override *is* in force — suite-wide, from conftest. The comment steers a future maintainer away from the per-test override while the actual shadow is the one they were just told to maintain by hand.

**Where AC-6 coverage actually stands** (accurate, and not alarming):

| Link | Guard | Genuine? |
|---|---|---|
| shipped default is `openid profile email` | `test_auth_config.py::test_settings_default_field_list_matches_fr1` | ✓ fails loudly on regression (proven above) |
| `settings.oidc_scope` propagates to the authorization request | `test_auth_oidc_login.py:81` | ✓ for the *route's* propagation — a hardcoded scope in the route would fail it |
| shipped default → real wire, as one chain | none automated; joined only by a hand-maintained conftest constant | ✗ (covered this round by the live 302 probe only) |

So AC-6 is **not** unguarded — a default regression is caught by the config test. What is missing is the *conjunction*, and the honest severity is lower than round-1 CF-1.

**Recommendation:** keep CF-1, reworded and downgraded to a low-severity test-fidelity item, with a concrete two-line fix — delete `"oidc_scope"` from `_HERMETIC_SETTINGS_DEFAULTS` (letting the field default flow through, which makes the wire test a real end-to-end guard and makes the new comment true), or, if the pin must stay for hermeticity, correct the comment to say what it actually asserts.
