## Manual OWASP checklist + stack-pattern pass

### Input (OWASP A03: Injection, A10: SSRF)

- Endpoint accepts **no request body and no query parameters** — `POST /api/admin/scan-repos` reads `org` and `token` from server-side `Settings` only. No user-controllable input flows into the outbound URL.
- Outbound GitHub URLs are built from `_GITHUB_API_BASE = "https://api.github.com"` (`Final` constant) + `settings.github_org` (env-controlled, admin-supplied) + `repo.name` / `default_branch` from GitHub's own JSON response. Base host is pinned; no user redirection is possible. **No SSRF surface.**
- Repo name / default branch come from a trusted upstream (`api.github.com`). GitHub's naming rules restrict them to `[A-Za-z0-9._-]`, so directory-traversal via f-string interpolation is not achievable in practice. See I-1 (info) for the belt-and-braces urllib-quote recommendation.
- No SQL string concatenation. All DB writes go through `sqlalchemy.dialects.postgresql.insert(...).on_conflict_do_update(set_=...)` — parameterised.

### Authentication and authorization (OWASP A01, A07)

- Router uses its own `HTTPBearer(auto_error=False)` and calls `get_ingest_token(program_id="*", …)` directly (D-05 pattern, matches `manifest.py` verbatim). All five denial branches from `app/core/ingest_auth.py` are inherited: 401 `missing`, 401 `unknown`, 401 `revoked`, 401 `expired`, 403 `scope`.
- Router-level **strict wildcard** re-check: literal `"*"` must be in `allowed_program_ids`, else 403 `wildcard scope required`. Legacy allow-all-empty (`[]`) tokens are rejected here even though `get_ingest_token`'s shared check accepts them per ADR-0006.
- Auth runs **before** the missing-config 500 check (TC-04, TC-07, TC-08 pin this order): no header → 401 even when `GITHUB_ORG` / `GITHUB_TOKEN` are unset.
- Ingest-token lookup is a SHA-256-hash indexed DB query. The raw token is never compared, so the raw-token compare has no timing side channel (the hash lookup timing depends only on B-tree probe depth, not user input).
- No new endpoint is added without an auth dependency; no route registers both `get_current_user` and `get_ingest_token` (FR-6 structural isolation).

### Data (OWASP A02: Cryptographic Failures, A04: PII)

- Response body contains **no PII**: three fields (`repos_total: int`, `repos_with_harness_installed: int`, `as_of_timestamp: datetime`).
- No new PII stored. Upsert on `org_summary_rollup` writes the three columns this feature owns plus timestamps — no user identifiers.
- `github_token` (PAT) stored via `pydantic-settings` from env only, typed `str | None`. Consistent with existing convention for `oidc_client_secret` (also `str | None`) — no in-repo use of `SecretStr` today. See I-1 for the optional hardening recommendation.
- No new DTO leaks internal fields — `ScanReposResponse` is a fixed 3-key schema; TC-12 asserts the OpenAPI component name and property set match verbatim.

### Crypto (OWASP A02)

- No new crypto primitives introduced by this diff. `hashlib.sha256` in `ingest_auth.py` is pre-existing and used as a **token identifier** (fixed-length pre-image), not for password hashing. Appropriate; no MD5/SHA1/DES/ECB anywhere in scope.
- TLS: httpx defaults to certificate verification (`verify=True`). No `verify=False` anywhere in the diff.

### Dependencies (OWASP A06)

- No manifest changes in diff. See § Dependency vulnerability scan above.

### Logs and errors (OWASP A09: Logging, A05: Misconfig)

- Every log record uses a **field allowlist**. Router: `admin_scan_started` = `{org}`; `admin_scan_failed` = `{org, error_kind, duration_ms}`. Service: `admin_scan_completed` = `{repos_total, repos_with_harness_installed, duration_ms, github_api_calls}` (matches D-07 field set exactly); `github_call_failed` = `{org, repo, attempt, duration_ms, status_code?, error_kind}`.
- **Never logged**: `credentials.credentials`, `settings.github_token`, the outbound `Authorization` header value, any GitHub JSON response body, `str(exc)`.
- `GitHubScanError` raises with a **categorical `error_kind` label only** (`timeout` / `rate_limited` / `upstream_5xx` / `http_error` / `non_retryable_status` / `invalid_response`) and uses `raise … from None` at the retry-exhaustion boundary to suppress the exception chain — a leaked upstream body in a subordinate exception cannot re-surface downstream. Confirmed by TC-17 which asserts a sentinel PAT + a `_SENTINEL_BODY` seeded in a 500 upstream response never appear in any structlog / caplog / admin-logger record, nor in the 502 response body.
- Client-facing 4xx/5xx responses go through `app.core.errors.register_exception_handlers` (ADR-0002 envelope): `{"error": {"code": "http_<status>", "message": <detail>, "details": null}}`. No stack traces, no internal identifiers leak.
- Denial-side (auth failure) audit event `ingest_token_auth_failed` still emits `{token_id, reason, program_id}` per FR-5 — no raw token, no `token_hash`.

### Stack-pattern pass

- **fastapi** (`.claude/skills/fastapi-patterns/SKILL.md`): `Depends()`-based session + auth (verified); `response_model=ScanReposResponse` pinned on route (strips extra fields on serialisation); `HTTPException` used for denial with distinct `detail` strings so tests can differentiate. ✅
- **pydantic** (`.claude/skills/pydantic-patterns/SKILL.md`): request-facing schema (`ScanReposResponse`) is a `BaseModel` with `Field(...)` metadata; `field_serializer` normalises `as_of_timestamp` to UTC-`Z`. No env/secret access inside a request/response schema (belongs only in `Settings`). ✅
- **postgres** / **alembic** (`.claude/skills/postgres-patterns/SKILL.md`, `.claude/skills/alembic-patterns/SKILL.md`): `pg_insert(...).on_conflict_do_update(set_=…)` — parameterised, no raw SQL. **No new migration** — feature reuses existing `org_summary_rollup` table; no schema drift, no alembic idempotency risk. ✅
- **Retry / timeout** (`.claude/rules/performance-baseline.md`): per-call `httpx.Timeout(10.0)` (bounded I/O); `retry_with_backoff(_once, max_attempts=4)` = 1 initial + 3 retries (exponential backoff + full jitter via `random.uniform(0, delay)`, max delay 2s per attempt); non-retryable 4xx fails fast without consuming budget. ✅

### Info (2)

#### I-1 — Optional hardening: consider `pydantic.SecretStr` for `github_token`; belt-and-braces urllib-quote for `org`/`repo` in URL construction

- Source: `stack-pattern/pydantic`, `stack-pattern/httpx`
- Severity: Info (not a finding — matches existing codebase convention)
- Evidence:
  - `services/api/app/core/config.py:108` — `github_token: str | None = None`. Same shape as pre-existing `oidc_client_secret: str | None` (`config.py:48`). No use of `pydantic.SecretStr` anywhere in the codebase; log discipline is enforced at each call site instead. **This matches project convention.** TC-17 provides the operational guarantee.
  - `services/api/app/services/repo_scan.py:209,240` — URL f-strings interpolate `org`, `repo`, `default_branch` without `urllib.parse.quote`. Values arrive from `settings.github_org` (admin-set) and GitHub's own response (`repo.name` / `default_branch` — GitHub restricts to `[A-Za-z0-9._-]`), so this is safe in practice. Belt-and-braces `quote(..., safe="")` would eliminate the theoretical URL-injection surface if GitHub ever loosens its naming rules or if a mis-configured proxy rewrites responses.
- Recommendation: not blocking — record as a future-defense observation. Any switch to `SecretStr` would touch `oidc_client_secret` too and belongs in a codebase-wide hardening story, not ING-07.

#### I-2 — Pre-existing transitive `postcss` advisories on `apps/web` (out of scope for ING-07)

- Source: `deps-scan/pnpm-audit`
- Severity: Info (pre-existing on `main`, ING-07 diff does not touch `apps/web` manifests)
- Evidence: `pnpm -C apps/web audit --prod --json` on `feature/ING-07` and on `main` both report the same four advisories, all against `postcss@8.4.31` transitive via `.>next>postcss`:

  | 4 | GHSA-r28c-9q8g-f849 — path traversal in previous-source-map auto-loading | high | CWE-22 | `<=8.5.17` | `>=8.5.18` |

- Scope: **not in ING-07's diff**. Per `security-assessment § Dependency vulnerability scan`, the scan is skipped when the diff touches no manifest — surfacing these here is informational courtesy. They do not flip the ING-07 verdict.

All four advisories concern build-time / dev-server `.map` and CSS stringify code paths (Next's own SWC minifier is used for production output; postcss handles CSS at build time), so the runtime blast radius on the deployed Next app is limited to the build/dev environment.
