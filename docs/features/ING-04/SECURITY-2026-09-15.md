### Runtime dependencies (declared in `pyproject.toml`)

#### F-DEP-01 — MEDIUM — fastmcp@2.14.7 command injection on Windows install path

- Source: deps-scan/pip-audit
- Advisory: PYSEC-2026-2475 (CVE-2025-64340, GHSA-m8x7-r2rg-vh5g)
- Path: dependencies > fastmcp
- Fixed in: 3.2.0 (blocked by pyproject pin `fastmcp>=2.0,<3.0`)
- Reachability: **not reachable in this deployment.** The vulnerability is in `fastmcp install claude-code` / `fastmcp install gemini-cli` — Windows-only CLI subcommands that shell out to `.cmd` wrappers. This service boots via `python -m agentrise_mcp` / `agentrise-mcp` console-script on Linux/macOS and never invokes `fastmcp install`. Reported at MEDIUM to reflect the underlying supply-chain risk if the pin is relaxed.
- Fix: schedule fastmcp 3.x upgrade in a follow-up story (relaxing the `<3.0` cap requires an ADR because fastmcp 3.x carries breaking transport changes per its release notes).

#### F-DEP-02 — MEDIUM — fastmcp@2.14.7 OAuthProxy consent-flow bypass (GitHubProvider)

- Source: deps-scan/pip-audit
- Advisory: PYSEC-2026-2476 (CVE-2026-27124, GHSA-rww4-4w9c-7733)
- Path: dependencies > fastmcp
- Fixed in: 3.2.0 (same pin cap as F-DEP-01)
- Reachability: **not reachable in this deployment.** The bug is in `fastmcp.server.auth.oauth_proxy.OAuthProxy._handle_idp_callback`. This service registers two tools via `@server.tool()` and calls `server.run(transport="streamable-http")` with no `auth=` kwarg; the OAuthProxy module is not imported nor instantiated (verified: `grep -r OAuthProxy services/mcp-server/src` returns nothing). MCP-tool auth is bearer-token in the *outbound* ingest call, not an OAuth *inbound* flow.
- Fix: same as F-DEP-01 — fastmcp 3.x upgrade in follow-up.

#### F-DEP-03 — MEDIUM — diskcache@5.6.3 pickle deserialisation RCE (transitive)

- Source: deps-scan/pip-audit
- Advisory: PYSEC-2026-2447 (CVE-2025-69872, GHSA-w8v5-vhqr-4h9v)
- Path: dependencies > fastmcp > diskcache
- Fixed in: **no upstream fix available** (advisory open as of 2026-09-15).
- Reachability: transitive via `fastmcp`. diskcache uses `pickle` by default; an attacker with write access to the cache directory can achieve RCE when the victim process next reads the cache. Precondition (local FS write on the process's cache dir) implies the attacker already has process-level access on the host, so realistic exploitation requires a co-tenant / shared-host scenario. The MCP server is designed for single-user local invocation (DATA-DESIGN § 4).
- Fix: track the upstream advisory (`diskcache` maintainer response) and revisit at fastmcp 3.x upgrade — 3.2.0 may pin a patched transitive.

## Manual OWASP checklist

Applied only to the diff surface (`services/mcp-server/**`, `docs/requirements/api.md` contract block).

### Input — PASS

- `.harness/program.yaml` deserialised with `yaml.safe_load` — no arbitrary Python object construction (`core/profile.py` L127).
- Every user-controlled string parsed out of `program.yaml` (glob patterns in `files[].path`, `artifacts.*.path`/`.glob`/`.exclude[]`; JSON keys in `artifacts.*.field`, `artifacts.*.exclude[]` for `json-key-count`) is passed through `validate_glob` / `validate_json_key` in `core/allowlist.py` **at YAML parse time** AND re-validated **at the resolver entry point** (sources/glob_count.py L45, sources/json_field_sum.py L43, sources/json_key_count.py L36). Rejects `..` traversal, absolute paths, `~` home-expansion, null bytes, shell metacharacters, JSONPath / JMESPath metacharacters (`[].$#@!?*`), whitespace, and non-printables.
- Resolvers additionally enforce workspace-root containment on every matched file via `Path.resolve()` + `is_relative_to(root)` (sources/glob_count.py L67, sources/json_field_sum.py L64) — a symlink pointing outside the workspace raises `SourceError` **and** the `push_activity` tool discards it silently (`push_activity.py` L92-95).
- No SQL, no shell exec, no template rendering — nothing to injection-vet beyond the above.

### Authentication and authorization — PASS with 1 MEDIUM note (F-01 below)

- Outbound to ingest backend: `HttpClient.post_json` unconditionally sets `Authorization: Bearer <token>` (`core/http_client.py` L45). Token loaded from env, fail-fast on missing (`core/config.py` L36-40).
- Inbound MCP transport: **no MCP-side auth** — see F-01 below.

#### F-01 — MEDIUM — inbound MCP server binds `0.0.0.0:3010` with no MCP-side auth

- Source: checklist/auth
- File: `services/mcp-server/src/agentrise_mcp/server.py` L27-29, L87
- Issue: `server.run(transport="streamable-http", host="0.0.0.0", port=3010, path="/mcp")` — the FastMCP server accepts unauthenticated MCP requests from any host on the LAN. Any reachable actor can invoke `push_activity` / `push_artifacts`. The tools themselves require `AGENTRISE_INGEST_TOKEN` in the server's own env (fail-fast at config load), so an unauthenticated caller cannot forge the *outbound* bearer — but they CAN (a) enumerate the two tools via MCP discovery, (b) trigger arbitrary reads of `<workspace_root>/.harness/program.yaml::files[]` (NDJSON files that may contain PII per DATA-DESIGN § 4), and (c) cause the server to POST the developer's activity/artifacts to the configured ingest endpoint using the developer's own token — an unauthorised push to a legitimate program. Risk profile: single-user developer laptop is the documented deployment surface (DATA-DESIGN § 3 "single-user by construction"), but the `0.0.0.0` bind exposes it beyond loopback.
- Contract source: FR-1 pins the bind (`0.0.0.0:3010`) as-is, so the exposure is a documented design decision — not a defect against the story. Reported here so it lands in the risk register and future stories (ING-05 client, remote deploy, etc.) surface the mitigation choice explicitly.
- Fix: options in preference order — (a) rebind to `127.0.0.1:3010` for local-only invocation (breaks LAN clients but preserves the documented single-user model); (b) require MCP-side auth (FastMCP transport-level auth kwarg — currently unused); (c) leave as-is with an explicit ADR documenting the LAN-trust model. Any of these must be recorded in DECISIONS.md and reflected in DATA-DESIGN § 3.
- Rule: `.claude/rules/security-baseline.md` — every protected endpoint enforces authn AND authz.

### Data — PASS

- Token classified SENSITIVE (DATA-DESIGN § 4). `Config.__repr__` / `__str__` return `"Config(ingest_token=<redacted>, ...)"`, `HttpClient.__repr__` returns `"HttpClient(base_url=..., token=<redacted>)"`, `HttpClient.__getstate__` raises `TypeError` to block pickle round-tripping (`core/http_client.py` L88).
- `TokenSuppressionFilter` (`core/logging.py` L104-142) substring-redacts the token in `record.msg`, positional/keyword `args`, and every non-standard field on `record.__dict__`; it also fully redacts any field whose key is on `_SECRET_KEYS` (`Authorization`, `authorization`, `bearer_token`, `token`, `AGENTRISE_INGEST_TOKEN`) regardless of value. Tests exercise every path (`tests/unit/test_logging_no_token_leak.py`, 8 cases including a canary bearer in the `url` extra).
- NDJSON row content (potentially-PII `email`, `command` free-text per `ActivityRowIn`) passes through the tool WITHOUT being logged. The `EventAllowlistFilter` (`core/logging.py` L96-102) drops any log record whose `event` field is not in the 13-entry allowlist — this is a positive-allowlist gate, not a redactor, so the row content cannot leak via a mis-named event.
- Config error on missing token names only the env-var (`f"{_TOKEN_ENV} is required but not set"` — `core/config.py` L37) — token value not present in the exception message.

### Logs and errors — PASS with 1 LOW note (F-02 below)

- 401/403 tool result envelope carries only `error`, `http_status`, and the FR-5 aggregate counters — no response body echoed back to the MCP client (`push_activity.py` L177-200, `push_artifacts.py` L188-204). No internal stack trace, no upstream error string, no bearer echo.

#### F-02 — LOW — `AGENTRISE_INGEST_BASE_URL` accepts unvalidated `http://` without warning

- Source: checklist/logs (config-drift)
- File: `services/mcp-server/src/agentrise_mcp/core/config.py` L43-46
- Issue: `load_config()` reads `AGENTRISE_INGEST_BASE_URL` verbatim, defaulting to `http://127.0.0.1:8000`. If mis-set to a non-loopback `http://` URL (e.g. `http://api.internal.example`), the bearer token is sent in cleartext over the network. There is no scheme check, no warning log, no deployment-mode gate.
- Fix: add a startup warning log when `AGENTRISE_INGEST_BASE_URL` has scheme `http:` AND host is not `127.0.0.1` / `localhost` / `::1`, and (optionally) fail-fast in a documented `AGENTRISE_ENV=production` mode. Non-blocking; the primary defence is that DATA-DESIGN § 4 pins the deployment to the developer laptop / loopback backend.
- Rule: `.claude/rules/security-baseline.md` — no PII in logs / no secrets on the wire in cleartext.
