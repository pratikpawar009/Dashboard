## 4. Contract-drift check — AF-02 focused (**FAIL**)

**AF-02 is confirmed as a real defect against the shipped backend.** This is the sole reason for the FAIL verdict.

Static three-way comparison (no live backend needed):

| Site | Fields |
|---|---|
| `services/api/app/schemas/ingest_files.py::IngestFilesResponse` (real wire contract, ADR-0013 / ADR-0012 / ING-02) | `received: int`, `valid: int`, `inserted: int`, `updated: int`, `rejected: list[RejectionEntry]`, `rollup_summaries: dict` |
| `services/api/app/api/ingest.py` — `@router.post("/{kind}")` returns `IngestFilesResponse` for `kind == "activity"` (routes `POST /api/ingest/activity`) | same as above |
| `services/mcp-server/src/agentrise_mcp/tools/push_activity.py` (lines 178–185 read the response body) | reads `body.get("rows_received", 0)`, `body.get("rows_upserted", 0)`, `body.get("rejections")` — **none of these keys exist on `IngestFilesResponse`** |

Because `dict.get(key, default)` returns the default silently when the key is absent, `push_activity` will always report `rows_received=0, rows_upserted=0, rejections=[]` against the real backend — regardless of how many rows the backend actually received / inserted / updated / rejected. The failure mode is a silent all-zeros counter; no exception, no log-detectable divergence.

The drift is also baked into the produced contract at `docs/requirements/api.md#mcp-tools` (`shape.tools.push_activity` documents the success envelope as `{success, batches_sent, rows_received, rows_upserted, rejections, ...}`). That contract file is what ING-05 will consume, so the drift will propagate downstream unless fixed here.

Cross-check on `push_artifacts` — **NOT drifted.** `services/api/app/schemas/ingest_artifacts.py::IngestArtifactsResponse` intentionally ships `rows_received / rows_upserted / rejections` (see the module docstring `"symmetric with IngestFilesResponse at the shape level"`), and `services/mcp-server/src/agentrise_mcp/tools/push_artifacts.py` (line 229–231) reads those exact keys. This confirms the defect is scoped to `push_activity` alone.

**Fix directive for the fix-loop:**

1. `services/mcp-server/src/agentrise_mcp/tools/push_activity.py` — rework the response-parse and success envelope to consume `received / valid / inserted / updated / rejected / rollup_summaries` from `IngestFilesResponse` (backend is source of truth per ADR-0013).
2. `services/mcp-server/tests/unit/test_push_activity.py`, `test_push_activity_auth_failure.py`, `test_push_activity_missing_token.py` — update the respx-mocked response payloads AND the assertions on the returned envelope to use the real field names.
3. `docs/requirements/api.md#mcp-tools` — replace the `push_activity` success-envelope line so it names the real fields (`received, valid, inserted, updated, rejected, rollup_summaries`) rather than the invented `rows_received / rows_upserted / rejections` set. This is the ING-05 consumer contract and must not ship drifted.

Also re-verify AF-03 alignment (missing-token envelope wording — `"AGENTRISE_INGEST_TOKEN is required but not set"` vs the PLAN R-08 structured `{error: "missing_ingest_token", message: ...}` form) at the same time; that is an independent open flag with the same class of divergence and the fix should settle both. It is NOT the cause of this FAIL — the fix-loop just gets a natural batching opportunity.
