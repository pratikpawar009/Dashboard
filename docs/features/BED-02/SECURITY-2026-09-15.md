## Manual OWASP checklist

Only categories touched by the diff are enumerated; untouched categories are not tick-boxed.

- **Input**: `validate_range` (`range.py:46-63`) validates the sole untrusted input at the FastAPI trust boundary — plain `str` type + explicit membership check against a `frozenset({"7d","30d","90d"})`. No coercion path can reach the underlying query. `range_to_start` (`range.py:66-83`) rejects a naive `now` with `ValueError` rather than coerce (D-06). Pagination helpers (`pagination.py:17-29`) clamp with `min(value, MAX)` and floor via `Query(..., ge=…)`. Compute functions accept typed ORM rows only (D-02) — never a raw query. No SQL construction, no shell, no `eval` — none of these idioms exist in the diff. **No finding.**
- **Authentication and authorization**: N/A — BED-02 introduces no auth surface (REQUIREMENTS.md § NFRs: "Security: N/A — this story defines no new auth surface"). No route is wired; consumer routers apply their own RBAC (AUTH-03 scope). **No finding.**
- **Data**: `validate_range` logs `route`, `param`, `rejected_value` on rejection (`range.py:53-60`). `route` and `param` are opaque identifiers. `rejected_value` is user-supplied but capped to 64 chars with an explicit `...<truncated>` marker via `_capped_rejected_value` (`range.py:37-44`) — the mitigation AF-03 accepted and shipped. Cap bounds log-volume amplification and truncates newline-injection attempts before they reach the JSON payload; container escaping remains `json.dumps`'s job. Compute layer (`rollup_compute.py`, `guardrail_compute.py`) returns counts/percentages/summary strings — no PII fields read or emitted. **No finding.**
- **Crypto**: `hashlib.sha256` in `format.py:70` for a stable per-`program_id` colour index. Not used for authentication, integrity, tokens, or passwords — the "no homegrown / no weak-hash-for-security" invariants don't apply. **No finding.**
- **Dependencies**: N/A — no manifest changed. **No finding.**
- **Logs & errors**: `JSONFormatter.format` (`logging.py:42-60`) merges `record.__dict__` extras into the payload with first-class-key precedence (`key not in payload` — an extra can never overwrite `timestamp`/`level`/`logger`/`message`, AF-01 was explicitly rejected as this being the intended behaviour). Reserved `LogRecord` attrs excluded via hardcoded `_RESERVED_LOGRECORD_ATTRS` (D-04). `json.dumps(default=str)` falls back to `str(value)` on unserialisable extras — a caller-supplied object whose `repr` contains PII/secrets could reach a log line **at call sites in downstream stories** (AF-02, deferred as `AF-02-carry`); BED-02 itself has no such call site — its only `extra=` invocation is bounded to `{route, param, rejected_value}` at `range.py:54-59`, none of which is a caller object. `format.py::format_duration` rejects negative input with `ValueError` (`format.py:143`) rather than silently rendering a positive duration — no error-swallowing. No route in this diff handles exceptions (Depends() failures propagate to the existing `register_exception_handlers` envelope, per `fastapi-patterns`). **No finding.**

## Stack-pattern pass (`fastapi-patterns`)

- Range validation lives in `app/dependencies/`, imported through the barrel — one `Depends()` per resource, matching the "inline `Query()` bounds, not hand validation" idiom for the trivial cases and layering business-logic rejection into a dependency for the non-trivial 400-not-422 case. Consistent with the "one APIRouter per resource" / "routers must not import each other" layering (`app.dependencies` doesn't import `app.api.*`; verified — `app/dependencies/__init__.py` module-structure comment calls out the deliberate constant duplication with `activities.py`).

No route in the diff catches and reshapes its own error — the anti-pattern is not present.
- Auth stub (`app/core/auth.py`) is not consumed by any BED-02 module — no `Depends(get_current_user)` usage introduced. Correct: `fastapi-patterns` § Security explicitly says "do not build RBAC/authorization logic against this stub".

- Pagination bounds are enforced by the dependency helper, not left to callers, satisfying `performance-baseline.md` ("pagination is mandatory on every list endpoint"). Both variants (offset/limit max 50, page/page_size max 100) match the existing `app/api/activities.py::MAX_PAGE_SIZE`.
