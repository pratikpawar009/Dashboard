### Independent empirical verification of the four flagged risk areas

1. **TC-05 differential-range (#427, R-6)** — confirmed against real `usage_events` data for `program_id=dashboard` (173 rows spanning 2026-08-26 to 2026-09-17): live endpoint returned `total_runs` = **59** (7d), **173** (30d), **173** (90d); cross-checked with a direct SQL count (`c7=59, c30=173, c90=173`) — exact match. Confirms the service reads `usage_events` (per-event `ts`), not the lifetime `program_commands` rollup (which has no time filter and would make `?range=` a no-op).
2. **D-02 no-404** — `GET .../does-not-exist-999/commands?range=30d` → `200 {"total_runs":"0","items":[]}`. Contrast-checked the sibling `/releases` route on the same unknown `program_id` → `404`, confirming the asymmetry is real and intentional, not an oversight.
3. **AC-2** — `GET .../dashboard/commands?range=1y` → `400 {"error":{"code":"http_400","message":"invalid_range"}}` (never FastAPI's default 422).
4. **AC-6** — `GET .../dashboard/commands?range=30d` (all users) → `total_runs="173"`; `GET /api/personal-usage/smoke@local?range=30d` (one of the two contributing users) → `commands.total_runs="1"`. Two independently-computed totals (173 vs 1), neither derived from the other — confirms AC-6 empirically, not just by code inspection.

Additionally verified: persona byte-identical (`developer`/`cio`/`architect` tokens produce byte-identical response bodies for the same program_id/range); Next.js proxy at `/api/proxy/program-detail/dashboard/commands` returns `401 {"error":"session_expired"}` with no token in body/headers when no `dashboard_session` cookie is present.
