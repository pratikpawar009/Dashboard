- **TC-03** (`test_deliberate_nullable_mismatch_is_detected`): monkeypatches a real column's `nullable` flag away from the fixture value, re-runs the *same* comparison helper (`_compare_column`) TC-02 uses, and asserts it returns a non-empty mismatch list naming `nullable mismatch`. Genuine — not tautological, and it reuses the production comparison path rather than a separate hand-rolled check.
- **TC-05** (`test_round_trip_comparison_detects_a_leftover_table`): creates a real extra table via raw DDL against the live disposable DB, snapshots before/after with the same `_snapshot_schema` helper TC-04's round-trip assertion uses, and asserts the snapshots differ and the leftover table is named in the diff. Genuine.
- **TC-07** (`test_alembic_check_detects_intentional_drift`): clones `Base.metadata` into a scratch `MetaData`, appends a column that does not exist in the live schema, runs the real `compare_metadata` diff against a live `MigrationContext`, and asserts the diff is non-empty and names both the table and the injected column. Genuine — uses the actual Alembic diff engine, not a stub.

None of the three degenerates to `assert True` or an unreachable branch. All three exercise the identical mechanism the corresponding positive TC (TC-02/TC-04/TC-06) relies on, which is the strongest form of "not vacuous" — a hand-rolled second check could itself be wrong in a way that happens to agree with the first.

One caveat, not a defect: TC-16's build-order check (`TestBuildOrder`) does not use `git log` (nothing has been committed to git yet this run — confirmed via `git log --oneline` showing only the initial scaffold commit) and instead reads `tasks.json`'s `completed_at` timestamps. This is a reasonable adaptation given the constraint, but it means TC-16 currently proves "the DAG's own bookkeeping is self-consistent," not "the file-authoring order actually happened in that sequence in git history" — a strictly weaker claim than the TC's original intent. Not a blocking finding since the `tasks.json` timestamps are populated by the same orchestrator that ran the tasks in dependency order, but flagged for the record: once this work is committed, a future run of this TC should switch back to `git log --follow` and no longer need this fallback.
